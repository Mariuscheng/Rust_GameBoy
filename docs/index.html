A.I. Journey

迎來 Vibe Coding 新時代

歡迎來到這個 Rust GameBoy 模擬器開發旅程！這不僅僅是一個普通的編程教學，而是利用 A.I. (Vibe Coding) 的強大力量來協助我們重構這台經典的 8-bit 主機。

Vibe Coding 的核心在於：你負責思考高層次的架構和遊戲機的硬體邏輯，而不需要從零開始手刻每一個位元運算，A.I. 將成為你的得力助手。

準備好了嗎？請點擊左側目錄，開始了解我們如何指示 A.I. 搭建各個模塊吧！

處理器 (CPU) - 模擬大腦

GameBoy 使用的是一顆類 Z80 的 Sharp LR35902 CPU。它擁有許多暫存器 (Registers) 和過百個 Opcode 指令。如果要手動寫這堆 switch/case 會讓人抓狂。

在 Rust 中，我們利用強大的 enum 和 Pattern Matching (模式匹配) 來優雅地處理這個問題，並且可以這樣給 A.I. 指示：

我們正在使用 Rust 開發 GameBoy 模擬器。請幫我實作 CPU 模組。 1. 請建立 Registers 結構體來表示 AF, BC, DE, HL 等 8-bit/16-bit 暫存器。 2. 使用 Rust 的 Enum 來定義各種 Opcode 指令類型。 3. 使用 Match 來根據讀取的 Opcode 匹配並執行對應的算術指令 (如 ADD, SUB) 和邏輯指令。請確保處理 GameBoy 特有的 Flag (Z, N, H, C) 行為。

你可以看到 A.I. 會為你生成類似以下結構的程式碼：

struct Registers {
    a: u8, f: u8,
    b: u8, c: u8,
    // ...
}

enum Instruction {
    ADD(Target),
    JP(Condition),
    // ...
}

match opcode {
    0x80 => { self.add(self.registers.b); },
    // A.I. 幫你補全剩下的 200 行配對！
}

透過精確的 Prompt，可以確保 CPU 的行為符合文檔，並充分利用 Rust 內建的安全性特性。

圖像處理 (PPU) - 像素的藝術

PPU 負責渲染背景 (Background)、視窗 (Window) 和精靈 (Sprites/OAM)。GameBoy 的螢幕大小為 160x144 像素。這部分的同步是最複雜的。

請幫我寫 GameBoy 模擬器的 PPU (Pixel Processing Unit)。 我們需要實作 Scanline 渲染機制。請建立一個可以管理 OAM、VRAM 和 LCD Control 暫存器的結構。請用狀態機 (State Machine) 來表示 PPU 的模式 (OAM Scan, Pixel Transfer, HBlank, VBlank)。

A.I. 會建議你用 enum PpuMode { HBlank, VBlank, OamScan, PixelTransfer } 來控制畫面的逐行渲染時序 (Timing)。

音效處理 (APU) - 8-Bit 旋律

APU 包含四個聲道：兩個方波 (Square Wave)、一個自定義波形 (Wave)，和一個雜訊 (Noise)。

請利用 Rust 實作 GameBoy APU 中的 Channel 1 (方波)。請實作 Sweep 功能以及 Duty Cycle。我們後續會將音訊緩衝區輸出給 SDL3 播放。

直接記憶體存取 (DMA)

OAM DMA 能夠在 160 個機器週期內將記憶體的資料瞬間複製到 PPU 的精靈屬性表中，我們需要精確地模擬這個傳輸延遲。

實作 OAM DMA 傳輸。當 CPU 寫入 0xFF46 暫存器時觸發。請模擬傳輸所需的 160 個 M-Cycles 延遲，在這段期間內 CPU 只能存取 HRAM。

... 還有更多

記憶體管理單元 (MMU)、卡匣控制器 (MBC1, MBC2...)、Joypad 輸入以及最後的 SDL3 介面整合。

使用 Vibe Coding 的訣竅在於：不要一次過叫 A.I. 寫完整個模擬器。 將需求拆分成上述的獨立模塊，先將結構和介面定義好，再逐步加入實作和通過測試（例如著名的 Blargg's test ROMs）。祝你在 Rust 的復古旅程中玩得開心！
