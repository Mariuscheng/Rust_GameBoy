> 歡迎來到 Vibe Coding 空間

這是一場與 A.I. 協同作戰的「Vibe Coding」之旅。這裡沒有枯燥的教學，只有人機協作的火花。

在這個專案中，我使用了 Rust 語言來開發這個 8-bit 的 GameBoy 模擬器。透過結構化的 Prompt (提示詞)，我一步步引導 A.I. 來完成這個專案。

我負責規劃整體的模擬器架構與除錯，而 A.I. 負責「肌肉記憶」——產出大量的 Rust 程式碼。這就是 Vibe Coding。

> 核心模組：用 A.I. 寫 CPU 指令

撰寫 GameBoy CPU (LR35902) 中數百個 Opcode 是一件非常機械化的工作。這正是 A.I. 發揮的最佳舞台。

A.I. Prompt (指令示範)：

「我正在開發 Rust GameBoy 模擬器。請幫我實作 `execute_instruction` 函式，用 `match` 語句處理 opcode 0x00 到 0x05。請確保使用 Rust 的 `wrapping_add` 與 `wrapping_sub` 來處理暫存器的加減法，並更新 Flag 暫存器。」

Rust 實作技巧：

A.I. 利用了 Rust 強大的 Pattern Matching，並且很好地運用了安全運算 (如 Wrapping) 避免整數溢位錯誤。

// A.I. 產生的 Rust 程式碼範例：
pub fn execute_instruction(&mut self, opcode: u8) {
    match opcode {
        0x00 => { /* NOP */ },
        0x04 => { 
            // INC B
            self.b = self.b.wrapping_add(1);
            self.update_zero_flag(self.b);
            self.clear_subtract_flag();
            self.update_half_carry_flag_add(self.b.wrapping_sub(1), 1);
        },
        0x05 => {
            // DEC B
            self.b = self.b.wrapping_sub(1);
            // ...
        },
        _ => panic!("未處理的 opcode: 0x{:02X}", opcode),
    }
}

> 顯示核心：PPU

PPU 的時序 (Timing) 是模擬器中最難纏的怪物。在這裡，我讓 A.I. 專注於狀態機 (State Machine) 的切換。

「請幫我寫一個 PPU 的 tick() 邏輯，根據累積的 cycles 在 HBlank, VBlank, OAMSearch 與 PixelTransfer 這四個狀態中正確切換。」

> 記憶體傳輸：DMA

OAM DMA 傳輸要求在 160 個週期內將資料轉移。A.I. 建議使用 Rust 的 slice copy 方法，比起一個 byte 一個 byte 複製，效能大幅提升。

> 還有更多元件...

整個系統還有很多部分是由 A.I. 的協助下完成的：

  • [+] MMU: 卡匣的 Bank Switching 管理
  • [+] APU: 聲音處理
  • [+] Joypad: 控制器中斷與輸入矩陣

簡介

這個專案以 A.I. 指示（prompt）為核心，逐步生成並調整模擬器各個子系統（CPU、PPU、MMU、AUDIO、IO）。我會把明確的 prompt 給 A.I.，要求它生成可編譯的 Rust 函式、測試用例與 debug 建議，並用小步提交與驗證方式逐步整合到本地程式庫。
